# 口播稿風格指南（script-style）

把 `source/` 裡的素材 轉成「唸出來不彆扭」的口播稿。三條底線任一不過，整稿重寫。

## 三條底線

1. **資訊保留度 ≥ 60%** —— 換說法，不是做摘要。
2. **去 AI 味** —— 句子短、口語、第二人稱都做到了，AI 腔調仍在，一耳朵就聽得出來。
3. **保持原文語言** —— 原文 zh-TW 就寫 zh-TW，原文 en 就寫 en；中英混排保留術語、產品名、代碼、專有名詞。口語化只調節奏與自然度，不改語言。

八條原則講**形式**，去 AI 味五類講**風骨**，兩者都壓在「資訊保留度」之下。

---

## 最高原則：資訊保留度 ≥ 60%（刪減不得超過 40%）

> 這條優先於下面所有規則。先確定資訊沒丟，再調形式與風骨。

**判定**（由獨立 reviewer 對照 `source/` 裡的素材 逐項判斷，**不做字數除法**）：

- 先把 `source/` 裡的素材 拆成**資訊單元**：關鍵數字 / 名稱 / 時間 / 論斷、具體案例、多步論證的中間步驟、反方觀點 / 限制 / 例外。
- 逐單元在 `script.md` 找對應，回報「保留 / 消失」，據此估出保留比例。
- 整體 **≥ 60%**，且消失的單元只能落在下面「允許大幅壓縮」那幾類。
- **論證鏈**（前提 → 結論、因果、對比）必須保留，可以換說法，不能跳步。

**允許大幅壓縮**：套話開場、重複總結、學術性鋪墊、引文出處的完整書目格式、客套結語。

**禁止壓縮**：

- 關鍵數字與數據（就算「翻譯成感受」也要保留原始數字本身）
- 具體案例 / 例子 / 故事
- 多步論證的中間步驟
- 反方觀點 / 限制條件 / 例外（最容易被一刀切掉）

**原文太長時**：不要硬縮。告訴使用者「原文資訊量按 60% 留存最少需要 ~N 分鐘影片」，讓使用者選拉長或拆集。**禁止**自作主張縮到 30% 再假裝做完了。

## 口播八原則（形式）

### 1. 口語化：書面語換成「唸出來不彆扭」的說法

| 書面語 | 口播 |
|---|---|
| 綜上所述 | 所以你看 |
| 具有非凡的意義 | 這件事真的挺重要 |
| 在……方面有顯著提升 | 在……上明顯變強了 |
| 該工具旨在 | 這東西是用來 |
| 筆者認為 | 我覺得 |
| 由此可見 | 你看吧 / 這就是為什麼 |
| 與之相反 | 反過來 |
| 據相關資料顯示 | 我查了一下 |
| 詳情請參閱 | 想看細節自己去翻 |

判斷標準：唸出來會不會覺得「這人怎麼這麼端著」？會就改。

### 2. 短句：每句 ≤ 20 字為基準

長句拆短句，逗號優先於複合句。

| 原文 | 改寫 |
|---|---|
| 儘管它在文字渲染方面有了顯著的提升，但在某些複雜場景下仍然會出現錯誤。 | 文字渲染確實變強了。但複雜場景下，它還是會翻車。 |
| 我們透過對比測試發現該模型在指令遵循能力上明顯優於上一代。 | 我做了一組對比測試。指令遵循這一項，比上一代強太多了。 |

講話的人不會喘不上氣，螢幕前的人也不會。

### 3. 第二人稱：多用「你 / 我們」，少用「使用者 / 讀者」

| 原文 | 改寫 |
|---|---|
| 使用者可以透過該介面實現 | 你只要調一下這個介面 |
| 讀者將會發現 | 你會發現 |
| 開發者需要注意 | 你寫的時候要小心 |
| 本文將介紹 | 我們來看一下 |

讓螢幕前的人感覺你在跟他說話，而不是宣讀公告。

### 4. 前三秒給出鉤子，接著補齊背景

三種通用鉤子：

- **懸念**：「這是真的嗎？」「我以為是 bug，結果……」
- **反差**：「這東西以前要 3 小時，現在 30 秒。」「上週還人人吹爆，今天就翻車了。」
- **利益**：「看完這條，你就能省下買外掛的錢。」

**禁止**（前兩類是 PPT 感，後兩類是假共情）：

- 自我介紹開場：「大家好，今天我們來講講……」
- PPT 標題感：「本期影片我們將探討……」
- 先鋪墊一堆背景才進正題
- 假共情鉤子：「我知道你最近一定很糾結 X」「你是不是也有這種感覺」
- 自我加權鉤子：「接下來我說的，可能會顛覆你的認知」

鉤子後先用一個具體場景交代背景。假設觀眾符合已定的受眾設定，但第一次接觸這個主題。先讓他知道眼前是什麼、事情為什麼重要、接著會解開什麼問題。第一次提到關鍵縮寫時順手解釋。背景講到足以跟上正文即可。

### 5. 節奏停頓：用 `---` 分隔每個完整想法

每講完一個完整想法，用一行 `---` 分隔。

```markdown
所以呢，這玩意兒真的挺誇張的。

---

舉個例子。前幾天我讓它畫一張海報，三秒就出。

---

但你知道最離譜的是啥嗎？連裡面的中文字都對了。
```

`script.md` 的正文直接寫要念出的文字。

### 6. 數字翻譯成感受（核心衝擊數字除外）

觀眾聽到具體百分比與大數字會走神。除非數字本身就是核心內容，否則翻譯成感受。

| 原文 | 改寫 |
|---|---|
| 準確率提升了 47% | 幾乎快了一倍 |
| 覆蓋 120 個國家 / 地區 | 全世界基本到處都在用 |
| 使用者數突破 1.2 億 | 現在已經是國民級應用了 |
| 推理速度提升 3.4 倍 | 比以前快多了，不用等 |

例外：**核心衝擊數字保留原值並強調**（「前後差了 100 倍」「3 秒 vs 3 小時」）。

### 7. 不堆結構詞 / 萬能模板

| 禁止 | 改法 |
|---|---|
| 首先 / 其次 / 最後 | 融進自然過渡，或直接砍掉 |
| 接下來我們看下面三點 | 直接講 |
| 總結一下 | 所以你看 |
| 下面進入第二部分 | 再看一個 |

觀眾不需要知道你的影片是幾段式 outline。**結構感從內容節奏來，不是從指令來**。

### 8. 具體例子優先，從「我」出發

| 抽象 | 具體 |
|---|---|
| 它有很強的能力 | 你給它一張貓的照片，讓它換成賽博龐克風，3 秒就出 |
| 效能優越 | 我那台 5 年前的舊電腦跑得動 |
| 使用者體驗良好 | 我媽第一次用，5 分鐘就上手了 |
| 應用場景廣泛 | 海報、簡報、表情包、PR 套圖都能整 |

「我做了一個測試」「我讓它畫」比「使用者可以」「通常情況下」親切一百倍。

## 去 AI 味：五類必清的腔調（風骨）

形式做到 ≠ 沒 AI 味。下面五類是 AI 寫口播稿最穩定的指紋。**寫完專門掃一次，逐條砍掉。**

> 唯一判斷標準：**這句話唸出來，一個真人會這樣說嗎**？不會就改。

### 一、假共情：開口就演「我懂你」

❌ 「我知道你最近一定很糾結 X」「你是不是也有這種感覺」「我能理解你的心情」

✓ 直接拋事實 / 鉤子。若原文確實需要共情，用有資訊量的方式：「這個坑我也踩過」比「我懂你的感受」真實十倍。

### 二、假深刻：用「恰恰 / 反而 / 正是」包裝平庸觀點

❌ 「你以為它強是因為模型大，恰恰相反……」「這反而是它真正可怕的地方」「正是因為它夠簡單，所以才……」

✓ 去掉轉折包裝直接說結論。自檢：「恰恰 / 反而 / 正是」那句去掉之後，意思變了嗎？沒變就刪。如果去掉後觀點變平淡，**它本來就平淡**，換內容，不要用修辭補救。

### 三、自我標榜：說正事前先給自己加權

❌ 「我必須很認真地說一句」「接下來我說的，可能會顛覆你的認知」「這一段你一定要聽完」

✓ 直接說。好觀點不需要預熱；怕觀眾划走，靠節奏（短句 + 鉤子）留人，不靠加權。

### 四、萬能模板：一聽就是 AI 寫的口頭禪

| 位置 | ❌ AI 模板 | ✓ 口播版 |
|---|---|---|
| 開頭 | 說白了 / 本質上 / 底層邏輯是 | 直接說「它就是 X」 |
| 過渡 | 一句話總結 / 換句話說 / 歸根結底 | 直接說那句話，不預告 |
| 包裝 | 在某種意義上 / 從某種程度來講 | 刪掉 |
| 結尾 | 以上就是本期內容 / 希望對你有幫助 / 感謝觀看 | 直接回答開場問題，再用幾句話講出觀眾該記住的重點。有適合的下一步時再補一句。 |
| 互動 | 你想讓我繼續講 X 嗎 / 留言告訴我 | 給具體動作：去 GitHub 搜 X / 留言聊聊你踩過哪個坑 |

### 五、排比堆砌：連續 ≥ 3 句同構

❌ 「不躲，不藏，不繞，不逃」「它會畫圖，會寫字，會做海報，會做 PPT」「高效，精準，強大」

✓ 保留最有資訊量的一兩句，其餘砍掉，或換成一個具體例子。真人講話不追求每段像對聯，允許粗糙，過渡句就讓它過渡。

## 落盤前的細節禁區

- ❌ emoji（除非使用者明確要求）—— emoji 是文字彈幕，不是講話
- ❌ 括號補充 ——「這個模型（一種基於 transformer 的架構）很厲害」，括號裡的話講不出來，併入正文或刪
- ❌ 書名號 / 引號羅列 ——「《XX 報告》指出」改成「我看了一份報告」
- ❌ 「哈哈哈」等口頭語堆砌
- ❌ 過度網路梗 —— 梗有保鮮期，除非主題就是網路梗

## 念出來測試（終極標準）

挑 3 段檢查唸起來的停頓與節奏。有實際音訊時，以聽感為準。

- 唸到哪句覺得「這話我說不出口」→ 那句是 AI 味
- 唸到哪句想跳過 → 那段是排比 / 自我標榜
- 唸到哪句想笑（不是內容好笑，是油膩）→ 那句是假共情

**改完再念，直到三段唸下來都自然為止。**

## 自檢 checklist

寫完 `script.md` 後，對照來源的資訊單元，修正遺漏與口播不順的地方。

- [ ] 資訊保留度 ≥ 60%（reviewer 對照 `source/` 裡的素材 逐資訊單元判斷，**非字數除法**）—— 最高優先，不過整稿重寫
- [ ] 關鍵數字 / 案例 / 論證鏈逐項對照 `source/` 裡的素材，沒有整段消失
- [ ] 沒有 emoji / 書名號《》/ 括號補充 /「據 XX 報告顯示」類引文格式
- [ ] 段落只用 `---` 分隔，沒有章節標題、沒有 `<a id>` 錨點
- [ ] 每句 ≤ 20 字（基準），長句已拆
- [ ] 全文第二人稱
- [ ] 首句約 3 秒，提出有來源支撐的問題、反差或看點，正文有兌現它
- [ ] 正文前已用具體場景補足受眾需要的背景，讀者能說出主題是什麼、為什麼要看、接著會懂什麼
- [ ] 核心衝擊數字保留原值，其餘數字翻譯成感受
- [ ] 沒有「首先 / 其次 / 最後」結構詞
- [ ] 沒有「說白了 / 本質上 / 底層邏輯 / 恰恰 / 反而 / 正是 / 歸根結底」
- [ ] 沒有連續 ≥ 3 句同構排比
- [ ] 片尾直接回應開場問題，並用口語串起主要結論。若有下一步，放在總結之後
- [ ] 例子具體，且從「我」出發
- [ ] 三段念出來測試都自然

## 附註：平台變體（本版未納入）

B 站 / 抖音 / YouTube / 知乎 / 小紅書 各有單句長度、鉤子節奏、資訊密度的差異，本版只鎖 zh-TW 談話感，暫不收錄平台變體。未來若要擴充，在此表補上；去 AI 味五類對所有平台都適用。

> 去 AI 味不是降質。把「AI 在朗誦」換成「人在聊天」，資訊量一個不少，腔調全部換掉。換完之後如果內容變蠢，那是內容本來就蠢，該補內容，不是去 AI 味的鍋。
